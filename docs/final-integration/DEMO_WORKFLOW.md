# Verified local demonstration

Use fictional input only. Live mode is the default styled workspace; AI enrichment is MOCK.
The controller/HTTP integration test is repeatable with `npm.cmd run test:integration` and
uses a separate temporary process/database. It does not change the open local workspace.

1. Enter Admin. Paste a fictional Burmese chat order with phone 09790000000 and COD 25000.
2. Parse; inspect AMBER and reasons. Fill parcel description/day and Save original chat order.
3. Generate customer link, switch to customer, verify synthetic last-four 0000.
4. Submit explicit artificial test coordinates (0,0) as an initial proposal. This is not a home
   or township claim. Save availability/instructions. Approval is required where policy says so.
5. Return to the order, explicitly approve pending requests, record physical hub receipt and
   acknowledge unverified map accuracy, then prepare assignment to the selected rider.
6. Confirm route departure. Native route policy records DELIVERY_STARTED for assigned stops.
7. Open Rider, record delivery and actual COD after the existing two-second cancel window.
8. Submit handover; Admin counts fictional cash and receives/closes the route. These are
   ledger assertions, not a payment integration or proof of real-world cash.
9. Read order/history. A second RED order can be corrected manually, dispatched and failed;
   return custody and closeout remain explicit, not automatic retry replanning.

prototype.html preserves device-local presentation, offline workflow, schematic maps,
phone/photo/route effects where present in the source. It is marked DEMO_SIMULATION and
its records are never implied to be backend storage. Legacy presentation assets remain
available without claiming telecom relay, real GPS, route optimization, independent pin
verification, live push, photo verification or measured confidence animations. No visual
browser test was possible; the selected real controllers and HTTP APIs were exercised.
