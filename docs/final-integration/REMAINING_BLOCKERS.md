# Remaining blockers

P0 before public access: production login and role/tenant authorization, secure deployment
and trusted proxy policy, a real PostgreSQL migration/transaction run, and privacy/retention
review. The current local session boundary intentionally gives its trusted developer test
roles; it must never be exposed publicly or used with real customer data.

P1 for broader MVP validation: real browser/mobile/CSS/accessibility tests (browser tool was
unavailable), actual teammate acceptance of the selected branch UI, trusted location data,
courier policy calibration, model/provider decision and an evidence-grounded optional adapter.
The TypeScript adapter is preserved but real AI is not activated or externally evaluated.

P2 after hackathon: notifications/messaging, strong buyer identity when required, calibrated
performance/quality pilots, multi-worker PostgreSQL races, offline sync for actual saved API
writes, route optimization, tracking, billing and finance reconciliation. Do not treat source
prototype effects or synthetic dataset results as these real integrations.

Route cash aggregates are a hackathon ledger, not financial settlement. Retry replanning
for failed routed parcels remains unsupported until return/cash closeout is reviewed. No
major new auth, paid services or production migration was attempted. No source branch or
unrelated local work was discarded to hide an incompatibility.
